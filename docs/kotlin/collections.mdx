# List, Set, Map, and operator directory

Start by choosing the correct shape:

| Shape | Meaning | Example |
|---|---|---|
| `List<T>` | Ordered; duplicates allowed; indexed | Search results |
| `Set<T>` | Unique elements by equality | Selected IDs |
| `Map<K, V>` | Unique keys associated with values | User by ID |

## See the behavioral differences

```kotlin
fun main() {
    val names: List<String> = listOf("Ada", "Ada", "Grace")
    val uniqueNames: Set<String> = names.toSet()
    val ages: Map<String, Int> = mapOf("Ada" to 36, "Grace" to 85)

    println(names)               // [Ada, Ada, Grace]
    println(uniqueNames)         // [Ada, Grace]
    println(ages["Ada"])        // 36
    println(ages["Missing"])    // null
}
```

A Set is not “a faster List.” It represents a different domain rule: duplicates have no meaning. A Map lookup is nullable because the requested key may not exist.

## Transformation pipeline

```kotlin
fun main() {
    val numbers = listOf(1, 2, 3, 4)
    val result = numbers
        .filter { number -> number % 2 == 0 }
        .map { number -> number * number }

    println(numbers) // [1, 2, 3, 4]
    println(result)  // [4, 16]
}
```

## Predict the output

```kotlin
fun main() {
    val values = listOf(1, 2, 2, 3)
    val changed = values
        .toSet()
        .map { it * 10 }

    println(values)
    println(changed)
}
```

<details><summary><strong>Reveal</strong></summary><p>The original remains <code>[1, 2, 2, 3]</code>. The Set removes the duplicate, and map returns <code>[10, 20, 30]</code> for the current insertion-preserving implementation. Do not treat incidental ordering from an arbitrary Set implementation as a universal business guarantee.</p></details>

<Admonition type="tip" title="Interview-ready foundation">
Choose List, Set, or Map from the domain's cardinality and ordering rules. Then choose operators by behavior: throwing versus nullable, first match versus all matches, new result versus mutation, one value per key versus many, eager versus lazy, and silent duplicate replacement versus validation.
</Admonition>
