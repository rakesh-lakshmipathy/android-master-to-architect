# Inline functions

A lambda is usually represented as a function object and called indirectly. For a small higher-order function, `inline` allows the compiler to copy the function body and eligible lambda body into the call site.

```kotlin
inline fun measure(block: () -> Unit) {
    val start = System.nanoTime()
    block()
    println(System.nanoTime() - start)
}
```

Conceptually, this call:

```kotlin
measure { performWork() }
```

can become code similar to:

```kotlin
val start = System.nanoTime()
performWork()
println(System.nanoTime() - start)
```

The exact generated bytecode is a compiler decision, but this mental model explains the feature.

## Why inline can help

- It can avoid creating a lambda object.
- It can avoid an indirect function call.
- It enables non-local returns from eligible lambdas.
- It enables `reified` type parameters.

Do not add `inline` to every function. Ordinary function calls are already efficient, and copying a large body into many call sites can increase bytecode and app size.

## Non-local returns

```kotlin
fun firstNegative(values: List<Int>): Int? {
    values.forEach { value ->
        if (value < 0) return value
    }
    return null
}
```

`forEach` is inline, so `return value` exits `firstNegative`, not only the lambda. This is called a **non-local return**.

Use a labeled return when you want to skip only the current lambda call:

```kotlin
values.forEach { value ->
    if (value < 0) return@forEach
    println(value)
}
```

## `noinline`

An inline function may need to store or pass one lambda instead of copying it:

```kotlin
inline fun runNowAndLater(
    now: () -> Unit,
    noinline later: () -> Unit,
) {
    now()
    queue.add(later)
}
```

`later` is marked `noinline` because it must exist as a value that can be stored. A `noinline` lambda cannot use a non-local return.

## `crossinline`

Sometimes an inline function calls a lambda from another execution context:

```kotlin
inline fun post(crossinline block: () -> Unit) {
    executor.execute { block() }
}
```

The lambda cannot safely return from its original caller after being placed inside another function object. `crossinline` forbids that non-local return while still allowing inlining.

<Admonition type="warning" title="Do not optimize by habit">
Use `inline` mainly for small higher-order utilities, required non-local-return behavior, or reified types. Measure performance-sensitive code. The compiler may warn when inlining provides no meaningful benefit.
</Admonition>

<Admonition type="tip" title="Interview-ready answer">
`inline` asks the compiler to copy a small higher-order function and eligible lambda bodies into the call site. It can reduce lambda allocation and call overhead, enables non-local returns, and is required for reified types. The trade-off is larger generated code, so it should not be applied everywhere.
</Admonition>
