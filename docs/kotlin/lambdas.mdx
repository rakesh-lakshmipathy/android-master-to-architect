# Lambdas

A lambda is an unnamed function that can be stored in a variable, passed to another function, or returned as a result.

```kotlin
val double: (Int) -> Int = { value -> value * 2 }
println(double(4)) // 8
```

`(Int) -> Int` is the function type: it receives one `Int` and returns one `Int`.

Read it from left to right:

1. `(Int)` — the lambda accepts one `Int`.
2. `->` — separates the inputs from the result.
3. The final `Int` — the lambda returns an `Int`.
4. `{ value -> value * 2 }` — `value` is the input; the final expression is returned.

<PlaygroundLink code={`fun main() {
    val double: (Int) -> Int = { value -> value * 2 }
    println(double(4))
    println(double(-3))
}`} />

<div className="expected-output"><strong>Expected:</strong> `8`, followed by `-6`.</div>

## Reading lambda syntax

```kotlin
val label: (Int, String) -> String = { id, name ->
    "$id: $name"
}
```

- Parameters appear before `->`.
- The body appears after `->`.
- The final expression becomes the returned value.
- The expected function type helps Kotlin infer parameter types.

## The implicit `it` parameter

For a one-parameter lambda, Kotlin can name the parameter `it` automatically:

```kotlin
val lengths = listOf("Kotlin", "Java").map { it.length }
```

Use `it` only when the meaning is obvious. In nested or longer lambdas, an explicit name is easier to read:

```kotlin
users.filter { user -> user.isActive }
```

Use `it` for a tiny, obvious lambda. Name the parameter when the lambda is nested, has several lines, or represents an important business object.

<PlaygroundLink code={`data class User(val name: String, val active: Boolean)

fun main() {
    val users = listOf(User("Ada", false), User("Rakesh", true))
    val activeNames = users
        .filter { user -> user.active }
        .map { user -> user.name }
    println(activeNames)
}`} />

<div className="expected-output"><strong>Expected:</strong> `[Rakesh]`.</div>

## Trailing lambda syntax

If the last argument is a function, the lambda can move outside the parentheses:

```kotlin
repeat(3) { index ->
    println(index)
}
```

If it is the only argument, the parentheses can disappear. This syntax is common in Compose:

```kotlin
Button(onClick = { viewModel.save() }) {
    Text("Save")
}
```

## Capturing outside values

```kotlin
var total = 0
val add: (Int) -> Unit = { value -> total += value }

add(5)
println(total) // 5
```

The lambda **captures** `total`, meaning it keeps access to a value declared outside its body.

It captures access to the variable, not a frozen copy of its old value. Every invocation reads and updates the current `total`.

<PlaygroundLink code={`fun main() {
    var total = 0
    val add: (Int) -> Unit = { value -> total += value }
    add(5)
    add(3)
    println(total)
}`} />

<div className="expected-output"><strong>Expected:</strong> `8`.</div>

<Admonition type="warning" title="Capture carefully">
A lambda that outlives an Activity, Fragment, View, or large object can keep that object reachable longer than expected. Lifecycle ownership matters more than the lambda syntax itself.
</Admonition>

## Callable references

When an existing function already has the required shape, pass a reference instead of wrapping it:

```kotlin
fun normalize(value: String) = value.trim().lowercase()

val result = listOf(" A ", " B ").map(::normalize)
```

Member references are also possible:

```kotlin
val lengths = listOf("A", "Android").map(String::length)
```

`::normalize` is a reference to the existing function. In this example, it replaces `{ value -> normalize(value) }` without changing the behavior.

<PlaygroundLink code={`fun normalize(value: String) = value.trim().lowercase()

fun main() {
    val normalized = listOf(" Kotlin ", " ANDROID ").map(::normalize)
    val lengths = listOf("A", "Android").map(String::length)
    println(normalized)
    println(lengths)
}`} />

<div className="expected-output"><strong>Expected:</strong> `[kotlin, android]`, followed by `[1, 7]`.</div>

## Lambdas with receivers

`StringBuilder.() -> Unit` means the lambda runs with a `StringBuilder` as its receiver, so its members can be called without a variable name.

```kotlin
fun buildMessage(block: StringBuilder.() -> Unit): String =
    StringBuilder().apply(block).toString()

val message = buildMessage {
    append("Hello")
    append(" Android")
}
```

This style powers builders and Kotlin DSLs, including many Compose APIs. Use it when the receiver provides a clear, focused vocabulary.

Execution of `buildMessage`:

1. `StringBuilder()` creates one mutable builder.
2. `apply(block)` runs the caller's lambda with that builder as `this`.
3. `append` calls update the same builder.
4. `toString()` creates the final immutable string.

<PlaygroundLink code={`fun buildMessage(block: StringBuilder.() -> Unit): String =
    StringBuilder().apply(block).toString()

fun main() {
    val double: (Int) -> Int = { value -> value * 2 }
    val message = buildMessage {
        append("Result: ")
        append(double(4))
    }
    println(message)
}`} />

<div className="expected-output"><strong>Expected:</strong> `Result: 8`.</div>

## Corner cases

### Nullable lambda versus lambda returning null

```kotlin
val optionalAction: (() -> Unit)? = null
val nullableResult: () -> String? = { null }
```

- `optionalAction` may contain no function at all.
- `nullableResult` always contains a function, but calling it may return null.

<PlaygroundLink code={`fun main() {
    val optionalAction: (() -> Unit)? = null
    val nullableResult: () -> String? = { null }

    optionalAction?.invoke()
    println("action exists = " + (optionalAction != null))
    println("result = " + nullableResult())
}`} />

<div className="expected-output"><strong>Expected:</strong> `action exists = false`, followed by `result = null`.</div>

### Android-only example

The `Button { ... }` snippet above requires the Compose compiler and Android/Compose libraries, so it cannot run in plain Kotlin Playground. The standalone lambda behavior is demonstrated by the surrounding Playground examples.

## Common mistakes

### 1. Too many `it` values hide the meaning

<div className="practice-bad">

**✕ Hard to read**

```kotlin
users.filter { it.orders.any { it.total > 1_000 } }
```
</div>

<div className="practice-good">

**✓ Clear names**

```kotlin
users.filter { user ->
    user.orders.any { order -> order.total > 1_000 }
}
```
</div>

Both compile. The second version makes it obvious which object owns `orders` and which object has `total`.

### 2. Capturing a Fragment in long-running work

<div className="practice-bad">

**✕ Avoid**

```kotlin
repository.loadUser { user ->
    binding.name.text = user.name // May run after the Fragment view is destroyed
}
```
</div>

<div className="practice-good">

**✓ Prefer lifecycle-owned collection**

```kotlin
viewLifecycleOwner.lifecycleScope.launch {
    viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.uiState.collect { state -> render(state) }
    }
}
```
</div>

The problem is not “lambdas cause leaks.” The problem is that the callback may outlive the View it captured. Give long-running work a lifecycle owner.

### 3. Capturing mutable loop state

<div className="practice-bad">

**✕ Surprising result**

```kotlin
var selectedId = 1L
val onClick = { println(selectedId) }
selectedId = 2L
onClick() // Prints 2, not 1
```
</div>

<div className="practice-good">

**✓ Capture the intended value**

```kotlin
val selectedId = 1L
val onClick = { println(selectedId) }
```
</div>

A lambda captures access to the variable, not necessarily a frozen copy of its old value.

<Admonition type="tip" title="Interview-ready answer">
A lambda is an anonymous function value. Its type describes its parameter and return types, such as `(Int) -> String`. Lambdas can capture outside values, use trailing-lambda syntax, and run with a receiver. Captures are convenient, but lifecycle and concurrency ownership must still be handled correctly.
</Admonition>
