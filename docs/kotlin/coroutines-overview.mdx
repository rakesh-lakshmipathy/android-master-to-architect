# Coroutines, structured concurrency, Flow, StateFlow, SharedFlow, and channels

<Admonition type="tip" title="Simple idea">
A coroutine is cancellable work that may suspend without blocking its thread. Structured concurrency gives that work an owner. Flow represents asynchronous values over time; StateFlow stores current state; SharedFlow broadcasts events/values; channels send values between coroutines.
</Admonition>

## How to study this chapter

Do not memorize operator names first. For every example, answer:

1. Who owns this work and when is it cancelled?
2. Which part suspends, blocks, or consumes CPU?
3. Which dispatcher executes each part?
4. How do failure and cancellation propagate?
5. Is every value required, replaceable, or allowed to be lost?
6. What happens when the collector disappears, the process dies, or the account changes?

Those questions turn coroutine syntax into production concurrency design.

Examples in this chapter use `kotlinx.coroutines`. Android examples also require AndroidX lifecycle/ViewModel libraries, so dependency-specific snippets are labeled rather than linked to a dependency-free Playground.
