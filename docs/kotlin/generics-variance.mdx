# Generics and variance, progressively explained

Learn this in order:

```text
Generic function -> Generic class -> Mutable-list safety problem
-> covariance (out) -> contravariance (in) -> star projection
```

## 1. Generic function

A generic function preserves a caller's type without separate String, Int, and User versions.

```kotlin
fun <T> second(items: List<T>): T? = items.getOrNull(1)

fun main() {
    val number: Int? = second(listOf(10, 20, 30))
    val word: String? = second(listOf("Kotlin", "Android"))
    println(number)
    println(word)
}
```

`T` is a placeholder chosen by the caller/compiler. Passing `List<Int>` produces `Int?`, not `Any?`.

## 4. Why `List<Dog>` can be read as `List<Animal>`

```kotlin
open class Animal(val name: String)
class Dog(name: String) : Animal(name)

fun main() {
    val dogs: List<Dog> = listOf(Dog("Pixel"))
    val animals: List<Animal> = dogs
    println(animals.first().name)
}
```

<PlaygroundLink code={`open class Animal(val name: String)
class Dog(name: String) : Animal(name)

fun main() {
    val dogs: List<Dog> = listOf(Dog("Pixel"))
    val animals: List<Animal> = dogs
    println(animals.first().name)
}`}>
  Run read-only covariance
</PlaygroundLink>

Reading a Dog as an Animal is safe. Kotlin declares read-only `List` as covariant.

## 5. Why `MutableList` cannot do the same

```kotlin
open class Animal
class Dog : Animal()
class Cat : Animal()

fun main() {
    val dogs: MutableList<Dog> = mutableListOf(Dog())
    // val animals: MutableList<Animal> = dogs // compile error
    // animals.add(Cat()) // would put Cat into dogs
    println(dogs.size)
}
```

<PlaygroundLink code={`open class Animal
class Dog : Animal()
class Cat : Animal()

fun main() {
    val dogs: MutableList<Dog> = mutableListOf(Dog())
    // Uncommenting the next assignment causes a type-mismatch compiler error.
    // val animals: MutableList<Animal> = dogs
    // animals.add(Cat())
    println(dogs.size)
}`}>
  Run, then try the unsafe assignment
</PlaygroundLink>

`MutableList` both returns and accepts `T`. It is invariant: `MutableList<Dog>` is not a subtype of `MutableList<Animal>`.

## 6. `out T`: producer

```kotlin
open class Animal(val name: String)
class Dog(name: String) : Animal(name)
interface Source<out T> { fun next(): T }
class DogSource : Source<Dog> { override fun next() = Dog("Pixel") }

fun main() {
    val animals: Source<Animal> = DogSource()
    println(animals.next().name)
}
```

  Run the producer example

`out` means values of `T` safely come out of the contract. The compiler restricts unsafe input positions.

## 7. `in T`: consumer

```kotlin
open class Animal(val name: String)
class Dog(name: String) : Animal(name)
interface Sink<in T> { fun accept(value: T) }
class AnimalSink : Sink<Animal> {
    override fun accept(value: Animal) = println(value.name)
}

fun main() {
    val dogSink: Sink<Dog> = AnimalSink()
    dogSink.accept(Dog("Milo"))
}
```

<PlaygroundLink code={`open class Animal(val name: String)
class Dog(name: String) : Animal(name)
interface Sink<in T> { fun accept(value: T) }
class AnimalSink : Sink<Animal> {
    override fun accept(value: Animal) = println(value.name)
}

    val dogSink: Sink<Dog> = AnimalSink()
    dogSink.accept(Dog("Milo"))
}`}>
  Run the consumer example
</PlaygroundLink>

A sink capable of accepting every Animal can accept a Dog. This reversed safe relationship is contravariance.

## 8. Star projection

`List<*>` means the element type is unknown. You may read elements as `Any?`, but cannot assume String or Int.

```kotlin
fun describe(items: List<*>) {
    for (item: Any? in items) println(item)
}

fun main() {
    describe(listOf(1, 2))
    describe(listOf("Kotlin", "Android"))
}
```

<Admonition type="tip" title="Memory aid">
Producer **out**, consumer **in**. If a type both produces and consumes the same parameter, invariance is often necessary.
</Admonition>
