# Gradle, Android build tools, variants, and optimization

Gradle executes a task graph. The Android Gradle Plugin (AGP) adds Android-specific models and tasks for manifests, resources, code, packaging, signing, testing, lint, and publishing.

## Build flow

```text
Source + dependencies + resources + manifest
→ generated code/resources
→ Kotlin/Java compilation
→ bytecode transforms/desugaring
→ D8/R8 DEX
→ resource processing/shrinking
→ packaging and signing
```

## Build types, flavors, and variants

- Build type: debug/release behavior, optimization, signing, debuggability.
- Product flavor: product/environment dimension such as free/paid or demo/prod.
- Variant: combination of build type and each flavor dimension.

Avoid multiplying flavors for values that can be runtime configuration. Variant count multiplies tasks, generated outputs, CI work, and maintenance.

## Dependency configurations

- `implementation`: dependency hidden from consumers' compile classpath when possible.
- `api`: exposed as part of a library module's public API.
- `compileOnly`, `runtimeOnly`, test configurations: specialized availability.

Overusing `api` increases recompilation and coupling.

## R8

R8 shrinks, optimizes, and obfuscates release code. Reflection, JNI, serialization, and dynamically referenced classes may need keep rules or generated adapters.

```kotlin
isMinifyEnabled = false
```
</div>

## Signing

Signing keys identify app updates. Keep release keys/secrets out of source control, restrict access, plan backup/recovery, and use Play App Signing where appropriate.

## Build performance

Measure with build scans/profile reports. Common improvements:

- Configuration cache and build cache compatibility
- Avoid dynamic/changing dependencies
- Reduce annotation processing; prefer incremental KSP where supported
- Correct module/API boundaries
- Avoid task code reading environment/time unpredictably
- Parallelize CI safely and cache verified inputs
- Track clean and incremental builds separately
